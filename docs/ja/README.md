# AI エージェントを分解する — GIS × LLM が組み上がっていくのを観察する

FOSS4G 向け 3 時間ワークショップの参加者用カリキュラムです。

このワークショップは、`geo-chat` という完全クライアントサイドの SPA を題材に、
「AI エージェント」の中身を **API リクエストのレベルまで分解して理解する** ことを目指します。
ただし今回は、完成品を作る（ビルドする）のではありません。**あらかじめ機能を 1 層ずつ
剥がした「章ブランチ」を用意してあり、それを `git switch` で切り替えながら、同じ 1 つの
GIS 課題が層を足すごとに少しずつ解けるようになっていく様子を観察** します。

geo-chat は、ブラウザ内で動く DuckDB-WASM（SQL 分析）・MapLibre GL（地図）・
Vega-Lite（グラフ）に、Anthropic Claude をエージェントとして組み合わせたアプリです。
「自治体を都道府県ごとに色分けして地図に表示して」と自然言語で頼むと、SQL が実行され地図が塗られます。

## 貫く 1 つの課題（through-line）

全章を通して、私たちはたった 1 つの依頼をエージェントに投げ続けます:

```
自治体を都道府県ごとに色分けして地図に表示して
```

- **`chapter/00-chat-only`（10 章）** ではこの依頼に **口で答えるだけ** で、何も塗れません。
- 層を足していくと、**SQL は回るが地図は塗れない → 塗れるが沈黙して壊れる →
  壊れが読めるエラーになる → スキルが品質を底上げする** と、同じ課題が段階的に解けていきます。
- `main`（60 章）では、その「解けている状態」を **自動テスト（evals）** で保証します。

**同じ課題・同じモデル・同じ API キー**。変えるのは「エージェントに持たせた層」だけ。
だから差が全部、層のおかげ（またはせい）だと分かります。

## 持ち帰りゴール（Transfer Goal）

> ワークショップの翌週、参加者が **自分のデータと業務課題に対して「ツール」と「スキル」を
> 自分で設計してエージェントに組み込み、その挙動を魔法ではなく API リクエストのレベルで
> 説明・デバッグできる。**

「仕組みを暗記した」ではなく「初見の課題に応用できる（転移）」がゴールです。
この教材は、上の一文に効くことだけに絞っています。網羅的な API リファレンスではありません。

## 章マップ — ドキュメント × ブランチ × 足す層 × 観察される変化

各章は「`main` から機能を 1 層ずつ **引き算** して作ったブランチ」に対応します。
番号は **ブランチ名と揃えて** あり（`00→10`, `01→20`, …）、取り違えを防いでいます。

| 章ドキュメント                      | ブランチ                | この章で「まだ無い / ここで足す」層   | 観察される変化                                                |
| ----------------------------------- | ----------------------- | ------------------------------------- | ------------------------------------------------------------- |
| [10-chat-only](./10-chat-only.md)   | `chapter/00-chat-only`  | ツールが 1 つも無い                   | 口で説明するだけ。**自信満々に、しかし誤った** 知識で答える   |
| [20-data](./20-data.md)             | `chapter/01-data`       | ＋データツール（SQL・組み込みデータ） | SQL は回りテーブルは作るが、**地図は塗れず「過剰約束」** する |
| [30-viz-naive](./30-viz-naive.md)   | `chapter/02-viz-naive`  | ＋可視化ツール（**検証なし**）        | 47 色コロプレスは成功。だが強制すると **沈黙して壊れた地図**  |
| [40-validation](./40-validation.md) | `chapter/03-validation` | ＋検証層                              | 同じ強制で **読めるエラー** が返り、正直に報告される          |
| [50-skills](./50-skills.md)         | `chapter/04-skills`     | ＋スキル＋前提ゲート                  | スキルが **軸順の NaN バグを直し**、凡例付きの面積コロプレス  |
| [60-evals](./60-evals.md)           | `main`                  | ＋ evals ハーネス                     | エージェントの **最終状態を成功率で自動検証**                 |

> **番号のずれについて**: ドキュメントは 10 刻み、ブランチは 00 始まりです。対応は
> **「10-chat-only ↔ `chapter/00-chat-only`」のように末尾の名前で合わせて** ください。
> 各章の冒頭に `git switch` コマンドを明記しています。

## タイムテーブル（3 時間）

各章は 25 分。導入で完成形（`main`）を見せてから、**わざと機能を全部剥がした状態に戻り**、
そこから 1 層ずつ足し直して観察します。

| 時間      | Step / 章                                         | 体験の中心                                                   |
| --------- | ------------------------------------------------- | ------------------------------------------------------------ |
| （準備）  | [00-setup](./00-setup.md)                         | clone / `npm i` / API キー / ブランチ切り替えの練習          |
| 0:00–0:15 | 導入＋完成形デモ（`main`）                        | まず「魔法」を見る。GeoAI の中での今日の位置合わせ           |
| 0:15–0:40 | [10. 口だけの AI](./10-chat-only.md)              | ツール無し。トークン予測・ステートレス・自信満々の誤答       |
| 0:40–1:05 | [20. 最初のツールとループ](./20-data.md)          | `agent.ts` 精読＋ DevTools で API 往復を実況。DuckDB 素振り  |
| 1:05–1:30 | [30. 可視化ツール（検証なし）](./30-viz-naive.md) | 宣言的 spec。強制プロンプトで「沈黙の破綻」を暴く            |
| 1:30–1:55 | [40. 検証層](./40-validation.md)                  | 同じ破綻が「読めるエラー」に変わる。検証 = 修復ループ        |
| 1:55–2:20 | [50. スキル = md 1 枚](./50-skills.md)            | progressive disclosure・前提ゲート。スキルが実バグを直す     |
| 2:20–2:45 | [60. evals — 成果物としての評価](./60-evals.md)   | `npm run test:evals`・`runEval.ts` 精読・自分の eval を書く  |
| 2:45–3:00 | クロージング＋[70-beyond](./70-beyond.md) 紹介    | 自分の課題への転移。最初のツールの description を 1 文で書く |

> **70-beyond について**: 最後の 15 分はチャレンジを **やり切る** のではなく、**選ぶ・
> 最初の一歩・クロージングの一文** に使います。チャレンジ本体は分量多めで、
> **ワークショップ後に各自のペースでやり切る** 前提です。

## 対象と前提知識

- **対象**: QGIS / PostGIS / GDAL を使いこなし、Python や JS も書ける GIS エンジニア。
  ChatGPT や Copilot は使うが、「AI エージェント」の中身はブラックボックスだと感じている人。
- **前提知識**: SQL（SELECT / JOIN / GROUP BY）、空間データの基礎（投影・ジオメトリ型）、
  コマンドラインと **Git（特に `git switch` / `git diff`）** の基本操作。
  LLM の内部知識は不要です（そこを学びに来る場所です）。
- **必要なもの**: Node.js 20 以上が動くノート PC、モダンブラウザ（Chrome / Edge / Firefox 最新）、
  Anthropic API キー（[00-setup.md](./00-setup.md) で取得します）。

## 「プロンプト」の 3 層

ワークショップ中の「プロンプト」は 3 層に分かれます。混同すると迷子になるので最初に区別します。

| 層                         | 何に入れる文字列か                                                            | 例                                        | どこで扱うか                       |
| -------------------------- | ----------------------------------------------------------------------------- | ----------------------------------------- | ---------------------------------- |
| ① 利用プロンプト           | 完成した geo-chat の **チャット欄** に打つ                                    | 「自治体を都道府県ごとに色分けして」      | 全章の「② 観察」で使う             |
| ② エージェント内プロンプト | **アプリの一部として組み込む** system prompt / ツール description / スキル md | 「このツールは SQL を 1 文だけ実行する…」 | **本命。** 20 章以降で読み解く     |
| ③ 開発プロンプト           | Claude Code 等 **コーディング AI に与える** 実装指示                          | 「このリポジトリに◯◯ツールを追加して」    | 70-beyond の実装手段（付録に収録） |

各章で剥がしたり足したりしているのは、ほぼ全部 **②の層**（system prompt のセクション・
ツールの description・スキル md）です。「②をどう設計すると①がうまくいくか」——
この連関そのものが、このワークショップの学習内容です。

準備ができたら [00. セットアップ](./00-setup.md) へ進みます。
