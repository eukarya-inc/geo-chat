# 地理空間エージェントを、失敗のたびに組み立てる — GIS × LLM を内側から見る

FOSS4G 向け 3 時間ワークショップの参加者用カリキュラムです。

このワークショップは、`geo-chat` という完全クライアントサイドの SPA を題材に、
「AI エージェント」の中身を **API リクエストのレベルまで分解して理解する** ことを目指します。
geo-chat は、ブラウザ内で動く DuckDB-WASM（SQL 分析）・MapLibre GL（地図）・
Vega-Lite（グラフ）に、Anthropic Claude をエージェントとして組み合わせたアプリです。
「自治体を都道府県ごとに色分けして地図に表示して」と自然言語で頼むと、SQL が実行され地図が塗られます。

エージェントは丸裸の状態から始まり、章を追うごとに一段ずつ能力を得ていきます。そして各章は必ず、
現在のスタックを壊す本物の空間データリクエストで締めくくられます。

## 持ち帰りゴール（Transfer Goal）

> ワークショップの翌週、参加者が **自分のデータに合ったツールスタックを見極められる**
> ——汎用ツールで十分なとき、知識のギャップがスキルを必要とするとき、そしてタスクが専用の
> 検証済みツールに値するときを見分けられる——そして **エージェントの挙動を API リクエストの
> レベルで説明・デバッグできる。**

「仕組みを暗記した」ではなく「初見の課題に応用できる（転移）」がゴールです。
この教材は、上の一文に効くことだけに絞っています。網羅的な API リファレンスではありません。

## 学習成果（Learning Outcomes）

ワークショップの終わりまでに、次を経験しています:

- 裸のモデルから完全な地理空間ツールスタックまで、あらゆる能力の階層でエージェントを動かし、
  各階層が本物の空間データリクエストで失敗する様子を見た
- スキル（マークダウン 1 枚）と専用ツール（description + schema + validation）でエージェントの
  能力を拡張し、ゲートで作法を強制する方法を学んだ
- 専用ツール対汎用ツール、低い床対高い天井、そしてログに残った挙動からツールスタックを進化させる
  方法——というトレードオフの勘所を掴んだ

## 対象と前提知識

- **対象**: QGIS / PostGIS / GDAL を使いこなし、Python や JS も書ける GIS エンジニア。
  ChatGPT や Copilot は使うが、「AI エージェント」の中身はブラックボックスだと感じている人。
- **前提知識**: SQL（SELECT / JOIN / GROUP BY）、空間データの基礎（投影・ジオメトリ型）、
  コマンドラインと Git の基本操作。LLM の内部知識は不要です（そこを学びに来る場所です）。
- **必要なもの**: Node.js 20 以上が動くノート PC、モダンブラウザ（Chrome / Edge / Firefox 最新）、
  Anthropic API キー（[00-setup.md](./00-setup.md) で取得します）。

## 「壊して学ぶ」— このワークショップの進め方

各章には **fail-first**（説明の前に、まず失敗を体験する）の「壊す瞬間」を仕込んでいます。
座学のように積み上げて動くものを完成させるのではなく、ここでの失敗はあらかじめ仕込まれた演出では
ありません——その章の時点のエージェントに、本物の空間データリクエストを投げた、正直な結果です。
今のツールスタックが力不足であることをまず目で見て、次にその理由を読み、そして次の章でエージェントに
その不足を埋める一片が手渡されます。壊す、それから説明する——この順番が肝です。

各章はすべて、次の 6 つの要素で統一されています:

1. **① これまでのエージェント** — 前章から一段成長したツールスタックの図
2. **② 新しいピース** — その章で加わる考え方と、geo-chat のどこにそのコードがあるか
3. **③ 動かしてみる** — この段階で確実に動くプロンプト
4. **④ ここで壊れる** — 現在のスタックを壊す、本物の空間データリクエスト
5. **⑤ 手を動かす課題** — 自分のデータ・手で試す
6. **⑥ 開発プロンプト例** — Claude Code 等に実装させるための指示（③の層。付録に集約）

## 用語: 「プロンプト」の 3 層

ワークショップ中の「プロンプト」は 3 層に分かれます。混同すると迷子になるので、最初に区別します。

| 層                         | 何に入れる文字列か                                                            | 例                                        | 扱う章                                  |
| -------------------------- | ----------------------------------------------------------------------------- | ----------------------------------------- | --------------------------------------- |
| ① 利用プロンプト           | 完成した geo-chat の **チャット欄** に打つ                                    | 「自治体を都道府県ごとに色分けして」      | 01–02（入口として体験）                 |
| ② エージェント内プロンプト | **アプリの一部として組み込む** system prompt / ツール description / スキル md | 「このツールは SQL を 1 文だけ実行する…」 | **本命。** 02〜03 で読み、03〜04 で書く |
| ③ 開発プロンプト           | Claude Code 等 **コーディング AI に与える** 実装指示                          | 「このリポジトリに◯◯ツールを追加して」    | 04 以降の実装手段（付録に収録）         |

③で作ったツールが賢く使われるかは②の description の書き方で決まる——
この **②③の連関そのもの** が、このワークショップの学習内容です。
