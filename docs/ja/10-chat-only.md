# 10. 口だけの AI — ツールを 1 つも持たない状態

> 完成形デモ（00 章）では、同じ Claude が SQL を流して地図を塗りました。
> ここでは **その全部を剥がした状態** に戻ります。ツールが 1 つも無いと、AI に何が
> できて何ができないのか——「エージェント」の一番下の地盤を触ります。

## ① この章の状態

```bash
git switch chapter/00-chat-only
# 開発サーバを再起動（Ctrl+C → npm run dev）
```

このブランチには **ツールが 1 つもありません**。`src/lib/ai/tools/index.ts` の
`createTools()` は実質 `return {}` で、エージェントに渡す道具が空です。system prompt も
**CORE セクションだけ**（役割・環境・回答ルール）で、データ・可視化・スキルの各セクションは
まるごと落としてあります。

- **ある**: チャット欄・Claude 本体・会話の往復。
- **無い**: `duckdb_query`（SQL 実行）、`load_builtin_dataset`（データ読込）、
  地図・グラフツール、スキル。つまり **世界に触れる手が 1 本も無い**。

この状態の Claude は、あなたのブラウザで直接動く ChatGPT のようなものです。
賢く喋れますが、それだけです。

## ② 観察

### 観察 1: through-line プロンプトを投げる

```
自治体を都道府県ごとに色分けして地図に表示して
```

**実機での挙動**: エージェントは **喋るだけ** です。ツールカードは 1 枚も出ません
（呼べる道具が無い）。代わりに、それらしい SQL——たとえば
`CREATE TABLE … ST_Read('https://nlftp.mlit.go.jp/…')` のようなコード——を
**マークダウンのコードブロックとして** 書き、「データをお持ちですか？それとも
サンプルデータで試してみますか？」と聞き返してきます。Map タブは変わらず、
テーブルも増えません。

> **面白いのは「やらないこと」**: このエージェントは、`<function_calls>` のような
> **ツール呼び出しの XML 構文を偽装して出力したりはしません**。理由は §③ で説明します。

### 観察 2: 知識を問う——自信満々の誤答

```
日本で一番市区町村が多い都道府県は？
```

**実機での挙動**: エージェントは **自分の記憶から答えます**。
「参考情報（2024 年時点の一般的な知識）: **埼玉県が最も市区町村数が多く（63 市町村）**、
次いで北海道、長野県…」と、断定的に、しかし控えめなヘッジ付きで答えます。

**ところがこれは、実データと照らすと間違いです。** バンドルされている `japan_cities` を
実際に数えると **北海道が 194 で断トツの 1 位**（埼玉県ではない）。エージェントは
データに一切触れられないので、**確信を持って、しかし誤って** 答えました。

> これは「AI は嘘つき」という話ではありません。**手が無いモデルは、実データを確認する
> 手段が無いので、記憶に頼るしかない**——その記憶が古かったり曖昧だったりすると、
> こうなる、という構造の話です。

## ③ なぜこうなるのか — LLM はトークン予測器で、記憶を持たない

### LLM がやっているのは「次のトークンの予測」だけ

「AI エージェント」という言葉は大げさですが、その中心にある LLM がやっていることは、
突き詰めれば 1 つです:

> **トークン列を入力し、次に来るトークンを予測して出力する。** これだけ。

チャットの返答も、コード生成も、後の章で出てくる **ツール呼び出しも、全部この同じ仕組みの上**
に乗っています。だから手が無い今、モデルにできるのは「もっともらしい続きのトークン列を
書くこと」——つまり **説明・提案・SQL のドラフト** だけです。実行はできません。

### なぜ偽のツール構文を出さなかったのか

以前、ツールを実装レベルで剥がした別のビルドでは、モデルが
`<tool_name>duckdb_query</tool_name>…` のような **ツール呼び出しっぽい XML を地の文として
垂れ流す** ことがありました。ところが今回の `chapter/00-chat-only` では、それが起きません。

違いは **system prompt** にあります。このブランチの CORE プロンプトは
「あなたはツールを通して作業する」とは言うものの、**具体的なツール名も、ツール呼び出しの
書式も一切列挙していません**。モデルには真似すべき「型」が無いので、偽装しようがなく、
素直に散文＋マークダウン SQL に落ちます。

> **見える原理**: モデルの出力は、与えた文脈（②プロンプト）が強く形づくります。
> 「ツールの語彙」を見せていないから、ツールを騙らない。ツール呼び出しとは結局、
> **モデルが学習した特定の出力形式にすぎない**——この見方は、20 章で本物のツールが
> 現れたときに効いてきます。

### AI はステートレス（記憶を持たない）

もう 1 つ、今のうちに刻んでおきたい事実があります。**モデルは API 呼び出しの間、記憶を
一切持ちません。** 「さっきこう言った」を覚えているのはアプリ側で、毎回 **会話履歴を
丸ごと送り直す** ことで「記憶しているように見せて」いるだけです。

今の chat-only では往復が 1 回だけなので、この点はまだ地味です。**20 章でループが現れると、
DevTools でこのステートレス性を自分の目で確認** できます。ここでは「モデルは毎回まっさらから
文脈を読み直している」とだけ覚えておいてください。だから **知識を問う質問（観察 2）にも、
その場の文脈だけを頼りに、記憶から答える** しかなかったのです。

## ④ 次の章で足すもの — 「手」としてのツール

観察 1 の欲求不満（「SQL は書けるのに実行できない」）が、次章の設計動機そのものです。

> **20 章で足すのは、モデルに世界を触らせる「手」＝ツールです。**
> まず `duckdb_query`（SQL を 1 文実行）と `load_builtin_dataset`（組み込みデータ読込）を
> 足します。これでモデルは、記憶に頼る代わりに **実データを見て** 答えられるようになります。

観察 2 の「埼玉県 63」も、20 章では `SELECT prefecture, count(*) …` を **実行して**
「北海道 194」と正しく答え直せるはずです。手が 1 本増えるだけで、
「自信満々の誤答」が「データに基づく正答」に変わる——それを次章で観察します。

## ⑤ diff の読みどころ — 何を足すと「手」が生えるか

この章（`chapter/00-chat-only`）から次章（`chapter/01-data`）へ、何が足されるかを見ます:

```bash
git diff --stat chapter/00-chat-only..chapter/01-data
```

主に現れるファイル:

- `src/lib/ai/tools/duckdbQuery.ts` — 最初のツール（SQL を 1 文実行）。
- `src/lib/ai/tools/loadBuiltinDataset.ts` / `builtinDatasets.ts` — 組み込みデータの読込。
- `src/lib/ai/tools/geocode.ts` — 住所→座標。
- `src/lib/ai/tools/index.ts` — `// CHAPTER SEAM: data tools` の中身が増え、
  空だった registry に 3 つのツールが載る。
- `src/lib/ai/systemPrompt.ts` — CORE だけだった prompt に
  `DATA_GUIDANCE` と `BUILTIN_DATASETS` セクションが足される。

**CHAPTER SEAM とは**: `src/lib/ai/tools/index.ts` と `systemPrompt.ts` に埋めてある
`// CHAPTER SEAM: <層名>` コメントは、「この 1 ブロックがまるごと 1 つの層」であることを
示す **層の継ぎ目** です。chat-only ブランチは、ちょうどこの継ぎ目でデータ層以降を
切り落として作られています。次章では、その継ぎ目に **データ層が戻ってくる** のを読みます。

次は [20. 最初のツールとループ](./20-data.md)。手を 1 本持たせて、エージェントの
「ループ」が初めて動き出すところを、コードと DevTools の両方で分解します。
